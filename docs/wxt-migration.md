# WXT extension development and builds

Crossmark uses [WXT](https://wxt.dev/guide/resources/migrate.html) for entrypoint discovery, manifest generation, bundling, development reloads and Firefox packaging. It replaces the custom Vite popup build, esbuild background build, per-build icon generation and shell ZIP script.

## Layout and compatibility

- `wxt.config.ts` configures the React module, Chromium 120 / Firefox 128 build targets and Manifest V3 for both browsers. Firefox's WXT default is overridden explicitly to retain MV3.
- `apps/extension/entrypoints/background.ts` wraps startup in `defineBackground`. Native listeners still register synchronously before asynchronous storage/network initialization. WXT emits a Chromium service worker and a Firefox background script.
- `apps/extension/entrypoints/popup/index.html` loads the existing React UI. The generated popup path changes from `index.html` to `popup.html`; smoke tests read that path from the generated manifest.
- `apps/extension/src` retains the UI, browser API polyfill, OAuth implementation, storage schema, sync engine and adapters. There is no data migration or change to bookmark reconciliation.
- `apps/extension/manifest.ts` preserves the permissions, CSP, Firefox add-on ID and data collection declaration. `apps/extension/chromium-key.json` retains the public Chromium key and therefore the unpacked extension ID and OAuth redirect.
- `apps/extension/public/icons` contains the same PNG icons previously generated by the build script. They are tracked extension assets copied unchanged by WXT.
- `tsconfig.json` extends WXT's generated types while retaining the previous indexed-access checking behavior. `.wxt`, build output, local browser configuration and environment files are ignored.

## Commands

Use Node.js 22 or newer. Run `npm install` (or `npm ci` for the lockfile); its `postinstall` runs `wxt prepare`.

| Command                    | Result                                                                    |
| -------------------------- | ------------------------------------------------------------------------- |
| `npm run backend`          | Start/configure the Convex development backend                            |
| `npm run dev`              | WXT Chromium development build and browser reloads                        |
| `npm run dev:firefox`      | WXT Firefox development build and browser reloads                         |
| `npm run build`            | Typecheck, then build both production extensions                          |
| `npm run build:chromium`   | Typecheck and build `dist/chromium`                                       |
| `npm run build:firefox`    | Typecheck and build `dist/firefox`                                        |
| `npm run package`          | Typecheck, then zip Chromium and Firefox production builds                |
| `npm run package:chromium` | Typecheck, build Chromium and create `dist/crossmark-chromium.zip`        |
| `npm run package:firefox`  | Typecheck, build Firefox and create `dist/crossmark-firefox.xpi` with WXT |
| `npm run lint:firefox`     | Build Firefox and run Mozilla's `web-ext lint`                            |
| `npm run sign:firefox`     | Build Firefox and submit it for unlisted AMO signing                      |
| `npm run check`            | Typecheck, build both browsers and run isolated tests                     |

WXT calls the Chromium target `chrome`; a config hook retains the existing `dist/chromium` path. Development output goes to `dist/chromium-dev` and `dist/firefox-dev`. It includes WXT's local reload tooling and development permissions/CSP additions. The development-only `connect-src` additions allow the selected WXT server and its WebSocket; production keeps the original backend-only policy. Install or distribute the production output from `npm run build`.

WXT opens disposable profiles by default. `wxt.config.ts` points `webExt.binaries` at `CHROME_BINARY` / `FIREFOX_BINARY` when set, otherwise the usual Chrome/Helium/Firefox install paths for this machine. Chrome is launched with `--disable-features=DisableLoadExtensionCommandLineSwitch` so `--load-extension` still works on Chrome 137+. Set `WXT_OPEN_BROWSER=0` to skip opening a window.

For a personal binary, persistent Chromium profile or always-disabled launcher, create an ignored `web-ext.config.ts` at the repository root; it overrides the shared `webExt` config:

```ts
import { defineWebExtConfig } from 'wxt';

export default defineWebExtConfig({
  binaries: {
    chrome: '/path/to/chromium',
    firefox: 'firefoxdeveloperedition',
  },
  chromiumArgs: ['--user-data-dir=./.wxt/chrome-data'],
  // Set disabled: true to load the dev build manually instead of opening a browser.
});
```

When loading Chromium development output manually, enable **Developer mode** in the extensions manager so background reloads remain enabled. Keep any optional persistent development profiles under the ignored `.wxt/` directory, never in source directories or a personal browser profile.

## Environment variables

Keep the existing public endpoint variables at the repository root:

```dotenv
VITE_CONVEX_URL=http://127.0.0.1:3210
VITE_CONVEX_SITE_URL=http://127.0.0.1:3211
```

Unset or empty values retain these loopback defaults. Both endpoints must be exact HTTPS origins, or HTTP origins on `127.0.0.1`/`localhost`, with no credentials, path, query, fragment or trailing slash. The manifest's host permissions and `connect-src` policy use the same endpoints as the background OAuth and Convex clients.

WXT loads `.env`, `.env.local`, mode-specific files such as `.env.production`, and browser-specific files such as `.env.firefox` or `.env.production.firefox.local`. Later files override earlier files; existing shell variables take precedence. Production builds use production mode; `dev` uses development mode. Restart WXT or rebuild after changing environment files. See [WXT environment variables](https://wxt.dev/guide/essentials/config/environment-variables.html) for the complete order.

Only public values belong in `VITE_` or `WXT_` variables: both prefixes can be bundled into the extension. Google credentials, `BETTER_AUTH_SECRET`, trusted origins and AMO signing secrets remain backend or signing-process configuration. Do not commit environment files or credentials. [Google OAuth setup](google-oauth-setup.md) is unchanged by the migration.

## Firefox distribution

`package:firefox` uses `wxt zip -b firefox` to produce the existing unsigned XPI name, with `manifest.json` at the archive root. Source zipping is disabled for this local-install command; it does not prepare or submit a store source-review bundle. A signed package is still required for permanent installation in release Firefox.

The existing signing wrapper runs `web-ext sign` against WXT's `dist/firefox`, with `AMO_JWT_ISSUER` and `AMO_JWT_SECRET` supplied in the shell. It writes `dist/signed/` and `dist/crossmark-firefox-signed.xpi`. No signing request is part of a normal build, package or lint command.

## Validation

Run `npm run check` and `npm run lint:firefox`, then the [browser validation steps](test-plan.md). Compare production manifests when changing WXT configuration: the permission lists, public Chromium key, Firefox ID, minimum browser versions, CSP and data collection declaration must remain compatible. WXT owns the generated background and popup entries.

The auth-route regression test derives the Firefox callback from the manifest factory. Endpoint tests reject insecure or malformed build configuration. Browser smoke checks load the generated extension, use its declared popup path, and exercise the real native bookmark and identity APIs in disposable profiles.

# Authentication and privacy

Crossmark uses an email and password to sign you in. It stores a salted password hash rather than your password. Email addresses are not verified. Crossmark does not read browser cookies or passwords used for a browser’s own bookmark sync service.

Your password is sent to the Crossmark server over HTTPS (local development can use HTTP). The extension does not save the entered password. It saves a sign-in credential in this browser so you can stay signed in. That credential is not included in the popup’s bookmark data or bookmark exports. Access to synced bookmarks requires a valid sign-in and a connected copy of Crossmark belonging to the account.

Crossmark sends bookmark titles, full URLs, folder structure, order, browser name, browser type and sync activity information to its server. It does not open bookmark URLs, read visited pages or collect browsing history. The server can read and process your bookmarks. End-to-end encryption is not implemented.

Signing out disconnects this browser, ends its sign-in session and clears its cached synced bookmarks and changes waiting to sync. It leaves the browser’s current bookmarks in place. Crossmark keeps the saved original bookmarks and identifiers used to match bookmarks and folders on reconnection. The saved original bookmarks include titles and URLs and remain until Crossmark’s browser data is cleared, including by removing the extension. Switching accounts does not erase that original copy. Sync changes waiting to be sent before signing out; export remains available without signing in.

Signing in recovers access to the account’s synced bookmarks. Before connecting, choose whether to replace this browser’s bookmarks with the account’s synced bookmarks or replace the account’s bookmarks with this browser’s bookmarks. Replacing the account’s bookmarks also updates all other connected browsers. There is no merge option. A new account starts with its first browser’s bookmarks. Individual bookmark edits sync normally after connection.

Crossmark saves this browser’s original bookmarks before it first connects and keeps that copy across sign-out, reconnects and account changes. **Disconnect and restore** removes this browser from sync before restoring those original bookmarks. It stays disconnected until you explicitly reconnect. The account’s synced bookmarks and other browsers are unchanged by restoring. If connecting fails, Cancel needs the server to check whether the browser connected and remove it from sync if needed; Cancel does not undo an account replacement that already happened. See [connecting and restoring bookmarks](bookmark-recovery.md).

Self-service password reset uses an emailed, single-use code when the operator configures Resend. Resend receives the destination email and reset code, but no bookmark data. Reset ends every session. The deployment operator can also set a new password with an internal Convex function, which ends every session (see [login setup](auth-setup.md#setting-or-resetting-a-password)). Sign-in and sign-up are rate limited on the backend.

Accounts created with the earlier Google login have no password until the operator sets one. Sign-out removes any leftover `storage.local.googleSession` record.

Legacy v0 credentials and enrollment records were retired in the local backend. Ownerless development collections remain archived and cannot be accessed through any account. The extension strips a legacy credential and keeps its old sync data in `crossmarkLegacy` for local recovery; native bookmarks become the source when a new account-owned collection is initialized. A pre-migration database export is saved locally under `.convex/` and is not distributed.

History, backups and tombstones currently remain on the backend without automatic expiry. Settings supports password-confirmed account deletion, removing the account, sessions and owned cloud collections, devices, history and backups. Native bookmarks and local copies on other browsers remain. Deployment backups and operator exports have separate retention policies. Very large accounts can exceed atomic deletion limits; see [login setup](auth-setup.md#self-service-reset-and-account-deletion). Automatic retention controls remain separate work. Local database files under `.convex/` and local environment files are ignored by Git. Cloud storage encryption is provided by the selected Convex deployment, not a separate client encryption layer.

Opt-in [extension debug mode](debugging.md) retains up to 500 structured events in background memory and prints them to the background console. It is disabled by default and never uploads logs automatically. Logs omit credentials, account details, bookmark content and raw error text; they include browser family, timestamps, operation outcomes, counts and durations. The opt-in persists locally across restarts and sign-out, but the log buffer does not. Users can disable logging, export the buffer and clear it; console messages and exported files must be cleared separately. Review activity metadata before sharing a report.
